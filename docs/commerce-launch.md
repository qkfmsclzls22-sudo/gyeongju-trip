# 경주트립 회원·예약·결제 개발본

2026-09-22 / 기준 소스: `qkfmsclzls22-sudo/gyeongju-trip`, `30594a9`

배포 범위: 사용자 승인에 따라 기존 홈페이지에 회원·예약·결제 기능을 반영합니다. 외부 계정과 데이터베이스 설정이 완료되기 전에는 준비 중 안내와 기존 네이버스토어 예약 경로를 표시합니다. 운영 데이터베이스 생성·마이그레이션 및 실제 소셜 로그인·카드 결제 검증은 별도로 완료해야 합니다.

## 구현한 고객 흐름

1. 홈페이지 메뉴의 `로그인·예약내역`에서 네이버 또는 Google 인증.
2. 첫 이용 시 서비스 이용약관, 개인정보 수집·이용, 만 14세 이상 동의로 가입 완료.
3. 투어 상세의 `날짜 선택·예약하기`에서 판매 회차·성인·어린이 인원 선택.
4. 예약자명과 휴대전화번호 입력, 취소 규정 확인.
5. 서버에 주문과 정확한 금액을 먼저 저장하고 15분 동안 좌석 확보.
6. 토스페이먼츠 SDK v2 카드 결제창으로 이동. 카드번호는 홈페이지 서버에 저장하지 않음.
7. 서버에서 회원 소유권·저장 금액·결제사 결과를 검증하고 결제 완료 처리.
8. `내 예약`에서 결제 상태와 출발 상태를 각각 확인하거나 취소 요청.

별도의 아이디·비밀번호 가입은 추가하지 않았습니다. 네이버·Google 최초 인증이 회원가입으로 이어집니다. 동일 이메일이어도 두 소셜 계정을 임의로 합치지 않습니다.

## 관리자 흐름

- `/admin/bookings`: 날짜·시작 시간·홈페이지 판매 정원·최소 모집 인원·성인/어린이 가격 등록.
- 회차별 모집 중 / 모집 마감 / 출발 확정 / 운영 취소 처리.
- 예약자 연락처·인원·결제 금액·취소 요청 조회.
- 결제사 상태 재조회와 금액을 확인한 전체/일부 금액 환불.
- 일부 금액 환불은 해당 예약 전체 인원의 취소입니다. 인원 일부만 취소하는 기능은 아직 없습니다.
- 운영 취소된 회차의 예약은 전액 환불만 허용합니다. 회차 취소가 자동 카드 환불을 실행하지 않으므로, 예약별 환불 처리를 마쳐야 합니다.
- 관리자는 이메일 추정이 아닌 `COMMERCE_ADMIN_IDS`의 내부 회원번호로 지정합니다. 회원번호는 내 예약의 `회원 정보`에서 확인합니다.

## 실제 연결에 필요한 항목

| 항목 | 준비할 설정 | 구현한 연결 주소 |
|---|---|---|
| 네이버 로그인 | 경주트립 애플리케이션, Client ID/Secret, 서비스 URL, 사전 검수 | `https://www.gjtrip.co.kr/api/auth/callback/naver` |
| Google 로그인 | Google Cloud OAuth 웹 클라이언트, Client ID/Secret, 동의 화면·게시 상태 | `https://www.gjtrip.co.kr/api/auth/callback/google` |
| 회원·예약 DB | PostgreSQL 접속 주소, 운영 지역·접근 권한·백업 정책 | `DATABASE_URL` |
| 토스페이먼츠 | 사업자 PG 계약·심사, API 개별 연동 테스트/라이브 키 | `/payments/success`, `/payments/fail` |
| 결제 상태 통지 | `PAYMENT_STATUS_CHANGED` 웹훅 | `https://www.gjtrip.co.kr/api/payments/webhook` |
| 배포 | 기존 Vercel 프로젝트의 보호된 환경변수 설정 권한 | `gyeongju-trip` |

네이버 로그인과 네이버페이는 서로 다른 기능입니다. 현재 코드는 카드 결제창 방식이며, 간편결제 노출 범위는 PG 계약·상점 설정에 따라 확인해야 합니다. 네이버·쿠팡에서 주문한 내역을 자동으로 가져오는 기능은 포함하지 않았습니다.

실제 비밀키를 채팅, GitHub 소스, 공개 파일에 넣지 않습니다. Vercel 환경변수의 서버 비밀값으로 설정합니다. 브라우저에 공개되는 키는 `NEXT_PUBLIC_TOSS_CLIENT_KEY`뿐입니다.

## 실행·설정

`.env.example`에 변수 이름과 기본 비활성 설정을 준비했습니다.

```bash
npm ci
# .env.example을 .env.local로 복사한 뒤 비밀값은 안전하게 입력
npm run db:migrate
npm run test:commerce
npm run build
npm run start
```

- `NEXTAUTH_URL`은 실제 접속하는 단일 정식 주소와 맞춥니다. 운영은 `https://www.gjtrip.co.kr`을 기준으로 구성했습니다.
- 네이버 개발자센터의 서비스 URL도 같은 주소로 등록합니다.
- 테스트 배포에서는 별도 DB, 테스트 키, 테스트 배포 전용 OAuth 콜백을 사용합니다. 운영 DB를 테스트에 공유하지 않습니다.
- 신규 PG 결제는 `COMMERCE_ENABLED=true`와 키 설정이 모두 충족된 경우만 열립니다.
- 실결제는 `COMMERCE_MODE=live`, 라이브 키 한 쌍, `COMMERCE_LIVE_APPROVED=true`가 모두 필요합니다.
- 설정이 없으면 간편 로그인 버튼은 준비 중으로 표시하고 기존 네이버스토어 예약 경로를 제공합니다. 가짜 로그인이나 가짜 결제 성공을 만들지 않습니다.
- DB 초기화는 테이블만 만듭니다. 허위 예약이나 가상 판매 회차를 생성하지 않습니다.
- 운영 반영 전에 기존 결제 경로에서 진행 중인 거래를 마무리해야 합니다. 이전 URL 쿼리만으로 만들어진 주문은 새 회원 주문으로 자동 이관하지 않습니다.

## 운영 전에 확정할 내용

1. **판매 회차·요금·최소 인원**: 기존 저장소 가격을 초기 입력값으로 사용했습니다. 불국사 24,800/19,800원, 박물관 25,000/22,000원, 야경 16,900원이며 최소 인원 기본값은 7명입니다. 최근 안내의 8명 기준과 차이가 있어 실제 운영 기준을 회차 등록 때 확정해야 합니다. 외부몰 프로모션 가격을 자동으로 복사하지 않습니다.
2. **예약 채널별 정원**: 네이버·쿠팡과 재고가 연동되지 않습니다. 홈페이지에 판매할 좌석만 배정해야 합니다. 관리자 기본 정원은 박물관 15명, 다른 두 상품 20명입니다.
3. **사업자·개인정보 고지**: `/terms`, `/privacy`는 기존 상품 안내와 구현한 처리 항목을 바탕으로 작성한 검토 초안입니다. 대표자·통신판매업 정보·개인정보보호 책임자, 실제 DB 제공자, 처리위탁 세부 사항, 국외이전 해당 여부와 고지/동의, 보존정보 분리·파기 운영 절차를 확정한 뒤 공개해야 합니다. 본 개발본만으로 법적 요건 충족을 보장하지 않습니다.
4. **환불 기준**: 현재 사이트 안내인 3일 전 100%, 2일 전 70%, 1일 전 50%, 당일 환불 불가를 초안에 옮겼습니다. 실제 약관과 적용 법령에 맞는지 확정해야 합니다. 고객 요청은 접수 기능이며 자동 환불은 아닙니다.
5. **고객 안내**: 자동 문자·알림톡·주문 이메일은 아직 연결하지 않았습니다. 관리자 예약 목록과 기존 현장 안내 방식으로 확인해야 합니다. 이전의 선택적 `ORDER_WEBAPP_URL` 전송 대신 DB가 주문 원본이 되도록 바꿨으며, 알림 연동은 후속 작업입니다.
6. **조회 범위**: 고객 화면 최근 100건, 관리자 예약 최근 200건·회차 180건을 표시합니다. 대량 내역 검색·다운로드·페이지 구분은 후속 확장 대상입니다.
7. **회원탈퇴**: 현재는 고객센터 접수 방식입니다. 자동 탈퇴·소셜 연결 해제·보존기간 만료 자동 파기 기능은 후속 운영 작업입니다.
8. **결제 결과 불명 상태**: 통신 오류가 나면 성공으로 단정하지 않고 좌석을 유지합니다. 웹훅 또는 관리자 `결제 결과 재확인`으로 복구합니다. 정기 자동 대사 작업은 아직 없습니다.

## 검증 결과와 남은 검증

- `npm run build`: Next.js 프로덕션 빌드 및 TypeScript 검사 통과.
- 변경 기능에 대한 ESLint 검사 통과. 전체 저장소에는 기존 `app/landmarks/[slug]/page.tsx`의 내부 링크 오류와 기존 이미지 경고가 남아 있습니다.
- 핵심 테스트 14개 통과: 입력 변조, 서버 금액 산정, 정원 제한, 주문 멱등성, 미동의 회원, 다른 회원 접근, 만료 주문, 결제사 응답 검증, 중복 승인·웹훅, 회차 취소 중 승인, 환불 재전송, 리다이렉트 검증, 실결제 활성화 제한.
- PGlite의 PostgreSQL 엔진으로 스키마와 거래 상태 변경을 검사했습니다. 실제 운영 PostgreSQL의 여러 연결에서 동시 결제하는 부하 검증을 대체하지 않습니다.
- 프로덕션 서버 HTTP 검증: 홈·로그인·세 투어 예약·약관·개인정보·내 예약 진입, 비로그인 API 차단, 다른 출처의 요청 차단, 설정 미완료 시 판매 비활성 확인.
- 이 환경의 원격 브라우저가 로컬 테스트 서버 접근을 차단하여 화면 스크린샷·휴대전화 시각 검증은 수행하지 못했습니다.
- 실제 소셜 계정 가입·재로그인, 테스트 카드 결제·취소, 모바일 카드사 앱 복귀, 실제 웹훅 재전송, 여러 연결의 마지막 좌석 동시 예약은 계정·DB 연결 후 반드시 확인해야 합니다.
