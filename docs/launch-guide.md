# 경주트립 개편본 운영 안내

## 이번 개편
- 남색·금색 중심의 공통 디자인, 모바일 메뉴와 상품 하단 예약 버튼
- 메인 / 전체 투어 검색·분류 / 세 상품 상세 / 단체여행 / 여행가이드 / 7개 유적지 / 회사소개 / FAQ / 문의 / 로그인·회원가입 / 마이페이지
- 날짜별 야경 시작 시각과 요금을 단일 상품 데이터에서 관리
- 회원가입 없이 네이버에서 예약 가능. 홈페이지의 날짜·인원 선택은 예상 금액 계산이며 네이버로 선택값이 전송되는 것으로 표시하지 않음
- 기존 AI 여행 도우미 유지, 상품·유적지 정보 통합
- 후기·할인율을 고정 숫자로 과장하지 않고 실제 네이버 후기 확인으로 연결
- 문의 API에 서버 검증, 필수 개인정보 동의, 외부 접수 성공 확인, 전송 실패 안내 추가

## 실제 네이버·Google 회원가입을 켜는 순서
1. 사업자 소유 Neon PostgreSQL 프로젝트를 준비하고 `db/001_members_and_orders.sql`을 SQL 편집기에서 실행합니다. 계정·주문 데이터는 브라우저 저장소에 저장하지 않습니다.
2. Vercel 환경변수에 `DATABASE_URL`, 충분히 무작위인 `NEXTAUTH_SECRET`, `NEXTAUTH_URL=https://www.gjtrip.co.kr`를 등록합니다.
3. 네이버 개발자센터에서 '네이버 로그인' 애플리케이션을 등록하고 홈페이지·개인정보처리방침·로고·회원가입 화면을 심사 제출합니다. 최소 필드는 고유 식별자, 별명, 이메일입니다. Callback URL: `https://www.gjtrip.co.kr/api/auth/callback/naver`. 발급된 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`을 Vercel에 등록합니다.
4. Google Cloud Console의 OAuth 동의 화면과 웹 애플리케이션 클라이언트를 설정합니다. 원본: `https://www.gjtrip.co.kr`. 리디렉션: `https://www.gjtrip.co.kr/api/auth/callback/google`. `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`을 등록합니다.
5. 실제 사용 중인 DB 리전·수탁사·국외이전 대상과 보유기간, 담당자 정보를 확인해 개인정보처리방침의 운영 내용을 확정합니다. 현재 개인정보 문구는 기본 안내이며 모든 법정 고지 항목의 완성을 보장하지 않습니다. 회원 기능을 켜기 전에 구체적 처리 내역을 채워야 합니다.
6. 등록된 정확한 도메인에서 네이버·Google 각각 신규가입, 재로그인, 동의 거절, 인증 취소, 로그아웃, 탈퇴 후 재가입을 확인합니다. 임의 이메일 계정 합치기는 하지 않습니다. 탈퇴한 세션으로 보호된 데이터에 접근할 수 없습니다.

인증키와 DB가 없는 경우 로그인 버튼은 준비 상태로 표시됩니다. 표시만 로그인 성공으로 바꾸는 모의 인증은 없습니다. 외부 인증 실동작은 해당 사업자 계정 설정 이후 확인할 수 있습니다. 미리보기 도메인을 쓰려면 별도 OAuth 콜백과 NEXTAUTH_URL을 해당 환경에 등록해야 합니다.

## 결제 준비 범위
기본 `COMMERCE_MODE=external`이며 네이버 판매를 유지합니다. 실제 결제를 켜는 기능은 이번 단계에서 제공하지 않습니다.

구현된 테스트 연결은 아래를 포함합니다.
- 인증된 회원의 서버 주문 생성 → 금액 스냅샷 저장 → 테스트 카드 결제창 → 서버 승인 확인
- 등록된 테스트 회차만 접수, DB에서 원자적으로 잔여 정원 확인
- 서버 단가 및 인원 검증, 과거 일정 거절, 주문 소유권 검사
- 주문별 멱등키, 이미 처리된 결제는 결제 조회 API로 orderId·paymentKey·상태·금액 재확인
- 승인 상태가 불확실한 주문은 성공 처리하거나 임의로 정원을 반환하지 않음
- 실제 결제 키 차단. `test_ck_` / `test_sk_`만 허용

테스트 시 `COMMERCE_MODE=test`, 테스트 키 두 개를 설정하고 DB에 향후 날짜의 테스트 회차를 `active=true`로 명시적으로 추가합니다. 테스트 키와 실제 키를 혼합하지 않습니다. 테스트 주문은 실제 고객 안내 문자·이메일을 보내지 않습니다.

실판매로 전환하려면 PG 가맹·심사, 통신판매업 및 사업자 고지 확인, 환불·취소/웹훅·승인 미확정 대사, 확정 알림·발송 재시도, 주문관리와 일정관리 연동, 개인정보 보관·파기 운영을 추가한 뒤 검증해야 합니다. 환경변수만 바꿔 실판매가 시작되는 구조로 만들지 않았습니다.

## 문의 운영
기존 Google Apps Script의 소유·관리 주체는 그대로 유지했습니다. URL은 서버에서만 참조합니다. `QUOTE_WEBAPP_URL`로 변경 가능합니다.
- 미리보기 배포에서는 외부 문의를 보내지 않으며 전송되지 않았다는 안내를 표시합니다.
- 이번 검증에서는 실제 이메일·시트로 테스트 문의를 발송하지 않습니다.
- 상담이 끝난 문의의 파기는 운영 중인 시트에서도 수행해야 합니다.

## 운영정보 확인 항목
- 기존 소개와 문맥상 사업자 대표자명이 일치하지 않는 부분이 있어 대표자명은 임의 확정하지 않았습니다. 실제 사업자등록증 기준 대표자·통신판매업 신고 정보는 직접 판매 공개 전에 반영합니다.
- 불국사 상품의 석굴암 방문·차량 이동 포함 범위는 예약 옵션에서 확인하도록 안내했습니다. 확정된 실제 포함 범위를 공유하면 상품 데이터 한 곳에서 변경할 수 있습니다.
- 가격은 기존 저장소 기준: 박물관 25,000/22,000원, 야경 16,900원, 불국사 24,800/19,800원.
- 할인율·별점·리뷰 수는 실시간 연동이 없으므로 고정 마케팅 수치를 삭제했습니다.
- 기존 소스에 미래 일정이 완료 실적으로 섞인 부분이 있어 회사소개는 확인된 설립·선정 연혁 중심으로 정리했습니다.
- 대릉원 무료 입장과 천마총 유료 관람을 구분했습니다. 변동 가능한 운영시간·관람료는 공식 안내로 연결합니다.

## 검증
`npm test`: 요금·입력 검증, 계절 시간, 결제 정보 일치, 리다이렉트·동의 서명, Postgres 스키마와 정원 점유/반환 검증.
`npm run build`: Next.js production build.
실제 OAuth, PG 승인, 운영 DB, 외부 문의 전송은 연결정보 없이 검증 완료로 표시하지 않습니다.
